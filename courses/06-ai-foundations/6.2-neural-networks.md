## Lesson 6.2 — Artificial neural networks

Linear regression can only draw a straight line. Neural networks fix that with a
surprisingly cheap trick: stack linear models in layers, and bend the output between each
layer.

You already know 90% of this. A neuron *is* the linear regression from lesson 6.1.

---

### One neuron

```
output = activation(w₁x₁ + w₂x₂ + … + wₙxₙ + b)
```

Weighted sum of inputs, plus a bias — that's `ŷ = w·x + b` again — then one extra step:
an **activation function** applied to the result.

### Why the activation function is the whole point

Stack two linear layers with nothing in between:

```
layer 1:  h = W₁x + b₁
layer 2:  y = W₂h + b₂
          y = W₂(W₁x + b₁) + b₂
          y = (W₂W₁)x + (W₂b₁ + b₂)
```

That collapses to `y = Wx + b`. A single linear layer. **Ten stacked linear layers are
mathematically identical to one linear layer** — you gained nothing.

Put a non-linear function between them and the collapse becomes impossible. That's the
only reason activations exist, and it's why a network can fit curves, spirals, images and
language while a line cannot.

**The ones you'll meet:**

| Activation | Formula | Use it for |
|---|---|---|
| **ReLU** | `max(0, x)` | Hidden layers. The default. Fast, works. |
| **Sigmoid** | `1 / (1 + e⁻ˣ)` | Output layer, binary classification (gives 0–1) |
| **Softmax** | `eˣⁱ / Σeˣʲ` | Output layer, multi-class (gives probabilities that sum to 1) |
| **Tanh** | `(eˣ − e⁻ˣ)/(eˣ + e⁻ˣ)` | Older networks, outputs −1 to 1 |

ReLU looks almost insultingly simple — "if negative, zero" — and it beat the elegant
smooth functions it replaced. Don't overthink it.

### Layers

```
input layer  →  hidden layer(s)  →  output layer
  (your data)    (learned features)   (the answer)
```

A network for recognising handwritten digits:

```
784 inputs        128 hidden          64 hidden         10 outputs
(28×28 pixels) →  (ReLU)          →   (ReLU)        →   (softmax)
                                                         one per digit
```

Each hidden layer learns features from the layer before. In an image network the first
layer typically learns edges, the next learns corners and curves, the next learns shapes.
Nobody programmed that hierarchy — it falls out of training.

**Parameter count** matters for intuition. Between 784 inputs and 128 hidden units there
are `784 × 128 = 100,352` weights plus 128 biases. Roughly 109,000 parameters in that
one layer. GPT-scale models do this with billions.

### Training: forward, loss, backward, step

Exactly lesson 6.1's loop, with one new word.

1. **Forward pass** — push inputs through the layers, get a prediction.
2. **Loss** — measure wrongness. MSE for regression, **cross-entropy** for classification.
3. **Backward pass (backpropagation)** — work out how much each weight contributed to the
   error, by applying the chain rule from the output backwards to the input.
4. **Update** — nudge every weight against its gradient. Same rule as before:
   `w ← w − α · ∂L/∂w`.

**Backpropagation is just the chain rule applied efficiently.** It reuses the gradients
from layer `n+1` when computing layer `n`, instead of recalculating from scratch — which
is the difference between "trains in an hour" and "trains in a decade". The maths is in
lesson 6.4.

You will essentially never implement it. PyTorch's `loss.backward()` does it. But know
what that line is doing, because when gradients explode or vanish, that's the line
failing.

### A real network, in PyTorch

```python
import torch
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(784, 128),
    nn.ReLU(),
    nn.Linear(128, 64),
    nn.ReLU(),
    nn.Linear(64, 10),
)

loss_fn = nn.CrossEntropyLoss()
optimiser = torch.optim.Adam(model.parameters(), lr=1e-3)

for epoch in range(10):
    for batch_x, batch_y in train_loader:
        optimiser.zero_grad()           # clear last step's gradients
        preds = model(batch_x)          # 1. forward
        loss = loss_fn(preds, batch_y)  # 2. loss
        loss.backward()                 # 3. backward
        optimiser.step()                # 4. update

    print(f"epoch {epoch}  loss {loss.item():.4f}")
```

Read that loop again next to the NumPy loop in lesson 6.1. Line for line, it is the same
algorithm.

> `optimiser.zero_grad()` is not optional. PyTorch *accumulates* gradients by default, so
> forgetting it means every step is polluted by every previous step. It is the most
> common beginner bug in PyTorch, and it fails silently — the model just trains badly.

### Vocabulary you need

- **Epoch** — one full pass through the training data.
- **Batch** — a chunk of examples processed together, typically 32–256. Faster than one
  at a time, and the noise actually helps generalisation.
- **Learning rate** — step size. Still the parameter most worth tuning.
- **Optimiser** — the update rule. `Adam` adapts the step size per parameter; use it
  unless you have a reason not to.
- **Dropout** — randomly zero some neurons during training so the network can't rely on
  any single one. A cheap, effective fix for overfitting.

### When it goes wrong

| Symptom | Likely cause |
|---|---|
| Loss is `NaN` | Learning rate too high. Lower it 10×. |
| Loss doesn't move at all | Learning rate too low, or you forgot `zero_grad()` |
| Train loss ↓, test loss ↑ | Overfitting — add dropout, get more data, or stop earlier |
| Both losses stay high | Underfitting — bigger network, or train longer |
| Works perfectly, suspiciously so | You leaked test data into training. Check your split. |

### Practice

1. Open [TensorFlow Playground](https://playground.tensorflow.org/), pick the spiral
   dataset, and try to fit it with **zero** hidden layers. Confirm it's impossible. Then
   add layers until it works.
2. Train the network above on MNIST. Get past 97% test accuracy.
3. Remove every `nn.ReLU()` and retrain. Accuracy should collapse towards what a linear
   model gets — that's the collapse-to-linear proof, run as an experiment.
4. Plot train loss and test loss on the same axes. Find the epoch where they diverge.
   That's the moment overfitting starts.
