## Lesson 6.1 — Linear regression

Every machine learning model, including the ones that write essays, is doing the same
three things:

1. **Guess** an output from an input, using some numbers called parameters.
2. **Measure how wrong** the guess was.
3. **Nudge the parameters** so it's slightly less wrong next time. Repeat.

Linear regression is the smallest possible example of this. If you understand it
properly, the rest of the module is detail.

---

### The model

Predict a number `y` from an input `x` with a straight line:

```
ŷ = w · x + b
```

- `w` — the **weight**, how steep the line is
- `b` — the **bias**, where the line crosses the y-axis
- `ŷ` ("y-hat") — our prediction. `y` is the real answer.

That's the whole model. Two numbers. "Training" means finding good values for `w` and `b`.

> With several inputs it becomes `ŷ = w₁x₁ + w₂x₂ + … + b`. Same idea — one weight per
> input. Written with vectors that's `ŷ = w·x + b`, which is where lesson 6.4 picks up.

### Measuring wrongness: the loss

We need one number that says how bad the current line is. For regression that's usually
**mean squared error**:

```
MSE = (1/n) · Σ (ŷᵢ − yᵢ)²
```

For each data point, take the gap between prediction and truth, square it, average over
all points.

Why squared? Two reasons that matter:

- Squaring makes errors positive, so being 3 too high and 3 too low doesn't cancel out
  to "perfect".
- Squaring punishes big misses much harder than small ones. Being 10 off is 100× worse
  than being 1 off, not 10× worse. That's usually what you want.

**Loss is the only thing training cares about.** The model doesn't know what a house or a
price is. It only knows one number went down.

### Gradient descent

We need to find the `w` and `b` that make the loss smallest. Picture the loss as a valley,
with `w` and `b` as your position on the ground and loss as altitude. You want the bottom,
and it's too foggy to see it.

What you *can* feel is the **slope** under your feet. So: step downhill, a little, over
and over.

The slope is the derivative of the loss with respect to each parameter — the **gradient**:

```
∂MSE/∂w = (2/n) · Σ (ŷᵢ − yᵢ) · xᵢ
∂MSE/∂b = (2/n) · Σ (ŷᵢ − yᵢ)
```

Then update each parameter by stepping against the gradient:

```
w ← w − α · ∂MSE/∂w
b ← b − α · ∂MSE/∂b
```

`α` is the **learning rate** — your step size, typically something like 0.01.

- Too small → training takes forever.
- Too big → you overshoot the bottom, bounce up the far wall, and the loss explodes to
  `NaN`. If your loss ever becomes `NaN`, lower the learning rate first. It's the cause
  nine times out of ten.

### From scratch, in NumPy

No libraries doing the thinking. This is the entire algorithm:

```python
import numpy as np

# y = 3x + 2, plus noise
rng = np.random.default_rng(0)
x = rng.uniform(0, 10, 200)
y = 3 * x + 2 + rng.normal(0, 1.5, 200)

w, b = 0.0, 0.0
lr = 0.01

for epoch in range(1000):
    y_hat = w * x + b
    error = y_hat - y

    loss = np.mean(error ** 2)

    dw = 2 * np.mean(error * x)
    db = 2 * np.mean(error)

    w -= lr * dw
    b -= lr * db

    if epoch % 200 == 0:
        print(f"epoch {epoch:4d}  loss {loss:7.3f}  w {w:.3f}  b {b:.3f}")

print(f"\nlearned: y = {w:.2f}x + {b:.2f}   (true: y = 3x + 2)")
```

Run it. Watch the loss fall and `w` climb towards 3. That output — a number going down
while parameters drift towards something sensible — is what training looks like, whether
the model has 2 parameters or 200 billion.

### The same thing with scikit-learn

In practice you don't write the loop:

```python
from sklearn.linear_model import LinearRegression

model = LinearRegression().fit(x.reshape(-1, 1), y)
print(model.coef_[0], model.intercept_)
```

Two lines, same answer. Write it from scratch once so you know what those two lines are
hiding.

### Train/test split — the habit that matters most

A model that has memorised your data will look brilliant and be useless. Always hold data
back:

```python
from sklearn.model_selection import train_test_split

x_train, x_test, y_train, y_test = train_test_split(x, y, test_size=0.2, random_state=0)
```

Fit on train, score on test. **A model is only as good as its score on data it has never
seen.** Every serious ML mistake you'll make in your career is a variation of forgetting
this.

- **Underfitting** — bad on train *and* test. The model is too simple. (A straight line
  can't fit a curve.)
- **Overfitting** — great on train, bad on test. The model memorised instead of
  generalising.

### What linear regression can't do

It fits a straight line. Real relationships are usually curved, and no amount of training
lets a straight line bend.

That's exactly the gap the next lesson fills: stack these linear units in layers, put a
non-linear function between them, and the result can fit almost any shape.
