# 1.1 — ANN Regression

A neural network that predicts a number. Not a category, not a word — a number.

This is the smallest one that can possibly work: **a single layer with a single
neuron**, which is to say a straight line. Everything larger — the networks behind
image models and LLMs — is this same loop with more neurons stacked on it. Learn the
loop here and the rest is scale.

Work through [`ann-regression.ipynb`](ann-regression.ipynb) alongside these notes.
The dataset, [`Student_Performance.csv`](Student_Performance.csv), sits next to it.

---

## The four things every network needs

Whatever the size, training needs exactly these:

| Piece | In the notebook | What it does |
|---|---|---|
| **Model** | `nn.Linear(1, 1)` | Holds the numbers that get adjusted |
| **Loss** | `nn.MSELoss()` | Scores how wrong a prediction is |
| **Optimiser** | `torch.optim.SGD(...)` | Decides how to adjust the numbers |
| **Loop** | `for i in range(1000)` | Repeats until the loss stops falling |

Miss one and nothing learns. That's the whole checklist.

---

## The model

```python
model = nn.Linear(1, 1)
```

One input feature, one output value. Inside are exactly two numbers:

- `model.weight` — the slope. How much the output moves per unit of input.
- `model.bias` — the intercept. Where the line sits when the input is zero.

So the model computes `y = weight * x + bias`. That's it. PyTorch initialises both
randomly, which is why an untrained model predicts nonsense. Training's whole job is
turning those two random numbers into good ones.

> `nn.Linear(1, 1)` is a one-neuron network. `nn.Linear(5, 32)` would be 32 neurons
> each reading 5 inputs — same object, bigger numbers.

## Shaping the data

```python
input  = torch.tensor(data['Sleep Hours'].values,  dtype=torch.float32).reshape(-1, 1)
output = torch.tensor(data['Hours Studied'].values, dtype=torch.float32).reshape(-1, 1)
```

Three things happen here, and each one matters:

1. **`torch.tensor(...)`** — pandas columns aren't tensors. PyTorch can't backpropagate
   through a NumPy array, so convert first.
2. **`dtype=torch.float32`** — gradients are fractional. An integer tensor can't hold
   them, and PyTorch will refuse rather than silently round.
3. **`.reshape(-1, 1)`** — the shape PyTorch expects is `(rows, features)`. A flat
   1-D tensor of 10,000 values becomes a `(10000, 1)` column. The `-1` means *work
   out this dimension yourself*.

Shape errors are the single most common PyTorch bug. When you hit one, print
`input.shape` before you do anything else.

## The loss

```python
error = nn.MSELoss()
```

Mean squared error: subtract prediction from truth, square it, average over all rows.

Squaring does two jobs. It makes every error positive, so a prediction 5 too high
doesn't cancel one 5 too low. And it punishes large errors disproportionately — being
off by 10 costs 100, being off by 1 costs 1. The model is pushed hardest to fix its
worst predictions.

**MSE is for numbers.** Predicting a category instead? That's `nn.CrossEntropyLoss()`.
Picking the wrong loss for the task is a quiet failure — training runs fine and learns
the wrong thing.

## The optimiser

```python
optim = torch.optim.SGD(model.parameters(), lr=0.001)
```

`model.parameters()` hands the optimiser the weight and bias — the things it is allowed
to change. It never touches your data.

`lr` is the **learning rate**: the size of each step. This is the one number you'll
tune most often.

- **Too large** — steps overshoot the minimum and the loss climbs, or becomes `nan`.
- **Too small** — it does converge, eventually, long after you've given up waiting.

If your loss goes to `nan`, lower the learning rate first. It's the cause most of the time.

## The training loop

```python
for i in range(1000):
    pred = model(input)
    loss = error(pred, output)

    optim.zero_grad()
    loss.backward()
    optim.step()
```

Every network you'll ever train is this loop. Read it once per line:

1. **`pred = model(input)`** — the forward pass. Run the data through and get predictions.
2. **`loss = error(pred, output)`** — score them. One number: how wrong we are.
3. **`optim.zero_grad()`** — clear last round's gradients.
4. **`loss.backward()`** — the backward pass. Work out, for the weight and for the bias,
   which direction reduces the loss. This is backpropagation.
5. **`optim.step()`** — nudge both numbers that way, by `lr`.

Then round two, with slightly better numbers. A thousand rounds later they've stopped
being random.

### Why `zero_grad()` is not optional

PyTorch **accumulates** gradients — `backward()` adds to what's there rather than
replacing it. Leave `zero_grad()` out and round 500 steps using the sum of all 500
rounds of gradients. Your loss explodes and the cause is invisible, because nothing
errors.

It's deliberate: accumulation is how you train on a batch too large to fit in memory.
But unless you want that, clear the gradients every round.

## Reading the result

```python
print(model(torch.tensor([[3.0]])))   # predict for 3 hours of sleep
model.weight                          # the learned slope
model.bias                            # the learned intercept
```

Note the double brackets in `[[3.0]]` — one row, one feature. The same `(rows, features)`
shape as the training data. Single brackets give a shape error.

The weight is the interesting one. It's the model's answer to *how much does the output
change per extra hour of input* — a claim about the data you can argue with.

## What this notebook gets wrong on purpose

Read the model's output sceptically. **Sleep hours barely predict study hours in this
dataset** — the two are close to independent. So the model does converge, and it
converges on a nearly flat line that predicts roughly the average for everybody.

That's not a broken notebook. That's what an honest model does with a feature that
carries no signal, and recognising the shape of that result is the skill. A low loss on
a flat prediction is not success.

Three other things it skips, deliberately:

- **No train/test split.** It's scored on the same rows it learned from, so you can't
  tell memorisation from learning.
- **No feature scaling.** These columns happen to be small. Mix in a feature ranging to
  100,000 and SGD at `lr=0.001` falls apart.
- **The loss is never printed.** You're training blind — no way to see whether it's
  still improving at iteration 1000 or finished at iteration 50.
